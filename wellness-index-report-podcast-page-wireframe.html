Form build constraints

  • Field 14 is a high-resolution file upload and field 15 is a signature. A plain inline form is unlikely to cover both, so this likely needs a form tool. Fields 11 and 12, a repeating link list and a Tue-Thu day and time-range picker with time zone, are also nonstandard for inline builders.
  • An embedded third-party form in an iframe arrives with its own styling that page CSS cannot reach. A previous build hit exactly this with an embedded HubSpot form that duplicated the page's branding and could not be restyled from outside.
  • Inline, embedded iframe, modal, and separate page each change what P8 actually looks like. The inline four-step version is drawn only so the block has a size and a place.

Layout patterns

Platform assumed GoHighLevel, not confirmed. Every proposed block is a standard drag-in pattern: hero, stat and logo strip, text band, ruled list, accordion, stepped form, two-cell band with disclosure rows. Three carryover flags for the builder: the populated-era episode filter is a listing pattern, not a static section; the Option A sticky bar usually takes a few lines of custom CSS; the P9 disclosure rows are the same accordion element the FAQ uses. The hero's listen link is a plain in-page anchor; its id lives on the episodes block and travels with it when the library splits back out.

Show name

The page title, nav label, hero eyebrow, P4 opening, and the form's agreement line read "The Wellness Index Report Podcast." Deck H1 and H2 headlines are verbatim. "Wellness Index Report" in P9's collapsed content and P11's populated body names the monthly publication, a different product, and stays as written.
